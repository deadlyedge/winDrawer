# winDrawer 下一阶段开发计划

> 状态：阶段 0–2 已实施；阶段 3/4 的大部分功能与测试已完成。本轮收尾依赖、构建产物和文档清理。旧配置自动迁移暂缓，不属于当前实现。
>
> 目标：把 winDrawer 收敛为一个易懂、可维护的 Windows 文件夹快捷入口。保留常见图片缩略图和当前 HSLA 主题调色功能（Hue、Saturation、Lightness、Alpha）；停止投入任意图标尺寸调优。

## 1. 已确认的产品行为

- 主窗口管理用户常用的文件夹；一次打开一个抽屉窗口，显示所选文件夹的直接子项。
- 抽屉采用普通文件列表，不递归扫描、不在抽屉内导航进入子目录。
- 单击条目只选择；双击把条目交给 Windows Shell 执行默认打开行为：目录通常在文件资源管理器中打开，文件由 Windows 默认关联程序打开。
- 采用 WinForms 内置 `ListView` 图标视图，使用系统 Shell 图标，不提供用户可调图标大小。
- 保留类似资源管理器的图片图标预览：至少支持 JPG/JPEG 和 PNG 缩略图，缩略图显示为列表项图标；不另开图片预览窗格。
- 保留当前主题设置页面的 HSLA 调色控件、窗口透明度、实时预览以及保存/取消流程；继续通过 Hue、Saturation、Lightness 和 Alpha 控件调整主题，不替换现有调色方式。
- 设置页提供可用的 Windows 登录启动选项；是否启用由用户设置控制。

## 2. 技术方向

- 保持一个 Windows Forms 应用项目，不先拆多项目，不引入复杂的 Clean Architecture、MVVM 框架或其他 UI 框架。
- 文件列表和图片缩略图使用 WinForms 原生控件。保留主题页现有 HSLA 调色控件与交互；主题设置继续持久化到现有 TOML 字段。其余现有控件按引用和简化收益逐项判断，不要把主题页或整个 UI 一次性重写。SunnyUI 只有在确认不再有引用后才可移除。
- 开发环境与目标框架使用 Microsoft 官方最新的 GA LTS .NET Windows 版本。按本计划编写时的决策，先以 `net10.0-windows` 为目标，并安装最新 .NET 10 servicing SDK；实际实施前再次核对 [.NET 官方支持周期](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core)。若已有更新的 GA LTS，则评估兼容后使用更新 LTS；不使用 preview/STS。NuGet 依赖升级到兼容目标框架的受支持版本，避免不必要的大范围升级。
- PowerToys / Command Palette 集成不纳入本阶段实现。等独立 MVP 使用体验明确后，再单独评估是否开发扩展。

## 3. MVP 范围

### 保留

- 主窗口显示已配置的常用文件夹。
- 添加文件夹；如果移除功能缺失或不可用，补上简单的移除操作。
- 选择文件夹后打开抽屉窗口；抽屉显示文件夹的直接子目录和文件。
- 系统托盘的显示/隐藏和退出操作（如果简化过程中没有额外负担则保留）。
- 设置页中的开机启动选项应尝试实际绑定当前 Windows 用户的登录启动；启用失败时应明确提示，不得只保存一个未生效的勾选状态。
- Shell 默认图标和 Windows 默认文件打开行为。
- 友好处理缺失目录、访问拒绝和 Shell 打开失败。
- 保留主题设置页当前的 Hue、Saturation、Lightness、Alpha/窗口透明度调节、实时预览、保存和取消；不得移除或替换现有 HSLA 调色控件。

### 删除或延后

- 自定义按钮皮肤。
- 每项自绘卡片、悬停着色、手绘滚动条和自定义缩放手柄。
- 用户可调图标尺寸和复杂的全目录缩略图缓存；JPG/JPEG/PNG 的列表项缩略图必须保留，不另开图片预览窗格。
- 在抽屉内导航子目录、复杂筛选/排序功能。
- 不实现需要管理员权限的全局开机启动；登录启动仅针对当前用户，并通过设置页控制。
- 多屏幕位置修复、边缘自动吸附等非核心行为。先使用普通、可移动/可调整大小的 Windows 窗口；确认用户确实需要后再单独恢复。

## 4. 建议的代码边界

保持单项目，控制文件数量。可逐步收敛到以下职责，不需要一次性重命名或搬动所有文件：

```text
Program.cs                         启动、全局异常处理
MainWindow.cs                      常用文件夹列表和窗口协调
DrawerWindow.cs                    ListView 图标视图和用户交互
FolderItemService.cs（或同等职责） 枚举直接子项、Shell 图标、Shell 打开、图片缩略图
Configuration/
  DrawerDefinition.cs              抽屉数据
  SettingsRepository.cs            加载、校验、保存设置
TrayController.cs                  可选：托盘生命周期
```

`FolderItemService` 只有在能把文件访问/Shell 操作从窗体代码中真正分离时才新增；避免只为形式上的分层创建接口和抽象工厂。

### `ListView` 实现注意事项

- 使用 `View.LargeIcon`（或经验证同样支持缩略图且更接近用户所需资源管理器体验的原生视图），由 `ListView` 负责项目排列、选择和滚动；按当前行为将文件夹和文件分组显示、名称忽略大小写排序。
- 单击仅更新选择状态。使用 `DoubleClick`/等效事件启动选中项，避免单次点击和双击重复启动。
- 文件和文件夹使用一致的 Windows Shell 默认 `open` 行为。优先通过 `UseShellExecute = true` 委托 Shell，不拼接命令字符串、不硬编码每种文件的执行程序。
- 复用 `ShellIcon.cs` 的现有实现或做最小必要调整，让列表使用合适的 Shell 小图标和系统 DPI 尺寸。不要再按用户输入的任意像素大小绘制图标。
- 对图标句柄和 `ImageList`/`Icon` 的所有权做好释放；不得在控件仍引用图像时提前 Dispose。
- JPG/JPEG/PNG 等常见图片应在 `ListView` 项目图标中显示缩略图；非图片项目显示 Windows Shell 图标。不另设 `PictureBox` 预览窗格。
- 缩略图尺寸使用单一、合适 DPI 的系统图标/列表尺寸，不提供尺寸设置。可复用现有 `TryCreateThumbnail` 或使用 Windows Shell 缩略图；不要引入复杂缓存。缩略图生成需避免锁定源文件，并在刷新/关闭时释放图像资源。损坏或暂时不可访问的图片回退为 Shell 图标，不影响列表和双击打开。
- 遍历使用 `Directory.EnumerateDirectories` / `EnumerateFiles` 等增量 API。访问失败要有可理解的错误提示；不要为假定的极大目录提前加入缓存、后台服务或线程池架构。

## 5. 配置和用户数据策略

- 优先延续现有 `Drawer-settings.toml` 和 TOML 字段。运行时设置文件默认位于 `%USERPROFILE%\.config\winDrawer\Drawer-settings.toml`；设置文件是用户数据，不是可随发布版本覆盖的模板。
- 保留已有抽屉名称、路径、顺序和可识别字段；移除 UI 功能时，不得静默把用户配置重置成默认值。
- 设置持久化只在添加/移除/修改等明确操作发生时写入。当前 672 行的后台写入循环对小设置文件过重，目标是简化为可靠的同步或简单合并写入；仍需避免写一半导致配置损坏，并报告写入失败。
- 暂不实现旧配置迁移。新配置默认创建于 `%USERPROFILE%\.config\winDrawer\Drawer-settings.toml`；程序目录中的旧配置不自动读取、复制或删除，需由用户自行处理。日志位置不由此次设置路径调整改变。
- TOML 模型序列化可能改变注释格式。实现前需验证 Tomlyn 当前写法是否保留用户字段/注释；不能静默丢弃用户的手动设置。必要时采用保留字段的编辑方式，或在迁移策略中明确备份并保留原文件。
- `start_with_windows` 是当前用户登录启动功能的设置来源，必须与实际启动注册状态保持一致；当前 `Behavior`、`Visual` 区域仍在使用的字段（包括 `window_locked` 和主题字段）应保持原有功能与语义。抽屉尺寸等不再使用的旧字段按兼容性策略忽略或保留，不得因简化 UI 而导致读配置崩溃。

## 6. 分阶段实施和验收

### 阶段 0：基线审查与 LTS 环境

1. 检查 `git status --short` 和将修改文件的 diff；确认当前工作树中的用户更改，不重置、不清理、不覆盖。
2. 在 Windows IDE/命令行安装并确认当前最新 GA LTS .NET SDK（当前目标为 .NET 10），检查相应 Windows Desktop/WinForms 组件；将项目目标设置为 `net10.0-windows`（若实施时已有更新的 GA LTS，则先评估并记录目标版本）。
3. 单独完成最小化的 TFM/NuGet 兼容调整，并先构建现有应用，区分环境升级问题和功能重构问题。
4. 阅读当前 `MainWindow`、`DrawerWindow`、`SettingsRepository`、`SettingsForm` 和 Designer 文件之间的事件/资源引用，再制定最小替换顺序。

**验收：** 有清楚的变更基线；项目使用当前最新 GA LTS Windows 目标且原有应用在该环境成功构建；没有丢失已有工作或配置。

### 阶段 1：资源管理器风格图标列表与 Shell 双击

1. 将 `DrawerWindow` 的自绘 `FlowLayoutPanel` 卡片列表替换为 WinForms `ListView` 图标视图（优先 `View.LargeIcon`），由系统控件负责图标排列和滚动。
2. 普通文件和目录显示 Windows Shell 图标；JPG/JPEG/PNG 至少显示图片缩略图作为该项图标，其他现有图像格式在当前 .NET 解码能力支持时可继续显示缩略图。
3. 移除用户可调图标大小；缩略图/图标共用单一、DPI 合适的显示尺寸。避免复杂缓存，缩略图失败则回退为 Shell 文件图标。
4. 单击只选择；双击将项目交给 Windows Shell 执行默认打开行为，验证文件和目录各自的系统默认行为。
5. 保留必要的刷新和关闭入口；使用常规窗口边框/原生缩放。

**验收：** 可显示普通目录中的文件和文件夹；JPG/JPEG/PNG 在列表图标位置显示缩略图而不是独立预览窗格；图标缺失或图片损坏时可回退；单击不打开；双击目录由资源管理器打开、双击文件由默认关联程序打开。

### 阶段 2：精简主窗口并保留现有设置功能

1. 保留 `SettingsForm` 当前已有的设置功能，以及 `Behavior`、`Visual` 两个区域中其他现有选项和行为；不得因布局调整删除或悄然改变这些设置。主题页继续使用当前 HSLA 调色方式，通过 Hue、Saturation、Lightness 和 Alpha/窗口透明度控件调整颜色，并保留调色板预览、实时预览及保存/取消行为。
2. 保持现有 HSLA 控件的工作方式：调整 H/S/L/Alpha 时更新颜色预览及主题实时预览；取消设置窗体时恢复原设置；保存时将四项 HSLA 值写回现有 `window_color_hsla` TOML 数组，不增加 RGB 中间选择流程。
3. 在 `Behavior`、`Visual` 之外新增 `General` 区域；将现有 `Shutdown App` 和 `Default` 按钮移入其中，并添加 `Open Settings TOML` 按钮。此项调整只改变区域归属和布局，不擅自改变既有按钮逻辑；实施时须核实 `Default` 的真实行为，不能把仅记录日志当作已实现的默认设置操作，也不要在本阶段自行扩大其行为范围。
4. 设置文件默认路径为 `%USERPROFILE%\.config\winDrawer\Drawer-settings.toml`，不实现从程序目录迁移旧设置。`Open Settings TOML` 使用 Windows Notepad 打开当前活动的设置文件；文件不可访问或 Notepad 启动失败时给出可理解的提示，不得导致应用退出。不得把该按钮实现成另一套设置编辑/保存流程。
5. 尝试让开机启动选项真正绑定当前 Windows 用户的登录启动：优先使用不需要管理员权限的用户级启动机制；启用/禁用时同步实际注册状态与 `start_with_windows` 设置，禁用时移除本应用的启动注册，并验证最终发布/运行路径在登录时可启动。注册失败时向用户说明且不得静默显示为已生效；不引入不必要的第三方依赖。若受部署或运行环境限制无法可靠实现，应记录具体限制并避免留下误导性成功状态。
6. 简化非核心自绘交互和按钮外观时不得删除其他现有设置功能；所选调色板仍应在主窗口/抽屉预览中有清楚反馈。不要删除主题页或把主题改为只能手工编辑 TOML。
7. 保留并验证常用文件夹列表、添加和移除操作、现有 Behavior/Visual 设置以及简单托盘控制。
8. 删除事件无效的控件、旧的自绘控件和不再使用的资产前，先搜索所有引用；SunnyUI 仅在没有剩余使用处时才移除。

**验收：** 普通窗口可清楚完成“选一个常用目录、查看图标列表、双击打开”；图片缩略图显示在对应列表项图标位置；现有设置功能没有因调整布局而丢失；设置页有独立的 `Behavior`、`Visual`、`General` 区域，`Shutdown App`、`Default` 和 `Open Settings TOML` 均位于 `General`；当前 HSLA 控件、实时预览及保存/取消正常；TOML 按钮以 Notepad 打开 `%USERPROFILE%\.config\winDrawer\Drawer-settings.toml` 并妥善处理失败；可验证开机启动启用、禁用及 Windows 用户重新登录后的行为，注册失败不会静默显示为成功；不存在看似有效却不工作的设置。

### 阶段 3：配置、日志和数据安全

1. 简化 SettingsRepository 的职责与代码；设置只在用户有明确变更时保存。
2. 验证缺字段、错误类型、损坏 TOML、无效/重复路径和目录不存在等情况。
3. 暂缓旧配置自动迁移。当前设置文件使用 `%USERPROFILE%\.config\winDrawer\Drawer-settings.toml`；不自动读取、复制、移动或删除程序目录中的旧设置。
4. 将新日志写入 `%USERPROFILE%\.config\winDrawer\Drawer.log`，与用户配置放在同一目录；暂不迁移程序目录中的旧日志。日志目录创建或写入失败均不得阻止应用启动。
5. 同步修订 `docs/CONFIGURATION_FORMAT.md`，准确说明当前 HSLA 调色控件与 `window_color_hsla` 字段的对应关系、General 区域新增选项、开机启动设置和配置文件位置；不为暂缓的旧配置迁移编造实现规则。

**验收：** 重启后抽屉列表和主题设置保持；不合法配置有可恢复处理；保存失败不会静默丢失旧文件；主题设置页与 TOML 字段有明确说明、配置文档与实现一致；日志位于用户配置目录，旧日志不被覆盖，日志失败不影响主功能。

### 阶段 4：清理、文档和回归

1. 审查 NuGet 包引用：SunnyUI 仍被窗体/Designer 使用，Tomlyn 仍被配置仓储使用，二者均保留。
2. 更新 README 的功能、配置位置、运行/构建方式和不再支持的特性。
3. 阶段 3/4 的配置与核心流程测试大多已完成；本轮只运行构建回归及文档/忽略规则检查，不重复已完成的手动验收，也不增加 UI 自动化测试框架。
4. 清理确认的根目录 `bin/`、`obj/` 生成内容，并从 Git 索引移除已跟踪的 `obj/` 生成文件；保留 `.vs/` 中的本地工作。若运行进程锁定输出文件，不强行终止进程，保留被占用项并记录。
5. Windows 回归检查：构建通过、文档与实现一致。旧配置迁移暂缓，不实现或测试迁移行为。

**验收：** Windows 构建通过；已完成的核心流程测试保持有效，本轮不重复全部手动测试；文档与实际行为一致；构建产物不纳入 Git；清理过程保留 `.vs/` 工作、日志及其他用户数据。

## 7. 本阶段不做的事

- 不开发 PowerToys 插件或新的系统级 Dock。
- 不嵌入 `IExplorerBrowser`/完整资源管理器 Shell 视图。
- 不切换到 WPF、WinUI 3 或跨平台 UI 技术。
- 不做自绘颜色选择器、全目录缩略图缓存、实时文件监控、递归索引、多目录同时弹出或高级搜索；保留当前 HSLA 调色方式的主题设置页，以及列表中的常见图片缩略图。
- 不做无必要的全量重命名/格式化/架构重写。

若 MVP 使用后确认这些能力有明确价值，再作为独立需求讨论。

## 8. 下一阶段：抽屉管理与窗口体验

> 本阶段承接阶段 0–4，不回头重做已完成工作。阶段 5.1–5.4 已实施；5.3 按后续使用反馈调整了右键触发、拖放位置提示和固定颜色蒙版强度。

### 已确认的产品行为

- Settings 中的 `window height` 表示主窗口客户区高度（96 DPI 逻辑像素），不限制抽屉总数或可视行数；抽屉列表按剩余区域自然滚动。
- 抽屉设置中的“位置”表示更改该抽屉绑定的文件夹路径；不表示改变主窗口列表排序或抽屉窗口屏幕坐标。列表排序通过单独的拖动重排操作完成。
- 抽屉窗口隐藏标题栏后，继续使用现有底部 `close` 按钮关闭窗口，并保留通过窗口边缘调整大小的能力；不增加无标题栏拖拽区域或自定义移动行为。
- 抽屉专属颜色可选。未设置时不叠加专属颜色蒙版；设置后固定以 70% 不透明度覆盖到该抽屉背景，不提供单独 Alpha 设置。
- 删除抽屉只移除应用中的快捷入口和配置，不删除、移动或修改磁盘上的文件夹及文件。

### 阶段 5.1：先显示抽屉窗口，再加载内容

1. 调整 `DrawerWindow` 生命周期，避免在构造和显示前同步枚举目录、排序并为所有图片生成缩略图。先显示窗口及“正在读取…”状态，再加载内容。
2. 避免耗时文件枚举和缩略图工作阻塞 UI 线程；控件更新仍须回到 UI 线程，并在窗体关闭、刷新重复触发或 DPI 变化时正确取消/丢弃过期工作。
3. 保留当前仅显示直接子项、目录和文件排序、Shell 图标及常见图片缩略图的行为。加载或刷新失败时提供可理解的状态，不因异常退出应用。
4. 不预先加入递归扫描、实时文件监控或复杂的全目录缩略图缓存。

**验收：** 抽屉窗口能先显示并保持响应，然后显示文件项；刷新只应用最新结果；关闭或 DPI 变化期间无跨线程控件访问、旧结果覆盖、卡死或图像资源泄漏。

### 阶段 5.2：抽屉窗口标题栏与底栏

1. 隐藏抽屉窗口标题栏；保留现有底部 `close` 按钮作为关闭入口，不新增标题栏关闭控件或无标题栏拖动区域。
2. 保留通过窗口边缘调整大小的能力，不实现自定义窗口拖动或屏幕位置管理。
3. 在底部文件夹路径旁显示 Windows Shell 的标准文件夹图标；图标和路径文本均可点击，并通过 Windows Shell 打开绑定目录。路径文本需妥善处理长路径。
4. 将刷新和关闭按钮换为合适的系统风格图标，并放入同一右对齐布局，保证窗口加宽时两按钮仍相邻靠右；为图标按钮提供可访问名称或提示。

**验收：** 标题栏隐藏后，底部关闭按钮正常关闭窗口、窗口边缘仍可调整大小；点击文件夹入口会打开对应目录；改变窗口宽度时刷新和关闭按钮仍相邻并靠右。

### 阶段 5.3：抽屉列表重排与右键设置

1. 主窗口中的抽屉条目支持拖动重排；拖动后立即更新列表顺序，并将顺序持久化到 TOML。重启后顺序保持，添加新抽屉不打乱已有相对顺序。
2. 对单个抽屉右键可打开抽屉设置窗口，支持修改名称、更换绑定文件夹、设置抽屉专属颜色和删除抽屉。
3. 路径更新须验证路径有效且不与其他抽屉重复；更新或删除只能作用于目标抽屉。更新路径时保留目标抽屉的颜色、名称/用户输入及其他有效设置，且不意外改变其列表位置。
4. 为抽屉颜色配置增加可选 RGB 字段；蒙版强度统一固定为 70%，不提供 Alpha 控件。旧配置缺少该字段时视为未设置；旧 ARGB 值读取时保留 RGB 并忽略原 Alpha。
5. 扩展 `DrawerDefinition`、设置快照和 `SettingsRepository` 以支持排序、编辑、路径更新、颜色及删除；尽量延续现有 TOML 结构，更新配置格式文档并为配置逻辑增加针对性测试。

**验收：** 拖动排序后顺序立即更新并在重启后保持；右键编辑后的名称、路径和颜色持久化；缺少新字段的旧配置仍可读取；重复或无效路径会被拒绝并说明原因；删除入口不影响磁盘文件；其它抽屉及目标抽屉的非编辑字段不会被误改。
### 阶段 5.4：设置主窗口高度

**状态：已实施**

1. 在 Settings 中增加主窗口高度滑块，单位为 96 DPI 逻辑像素；显示数值、实时预览，并保存到 `[startup].window_height`。
2. 默认客户区高度沿用当前值 400 DIP；滑块范围为 200–1000 DIP。旧配置缺少字段或字段类型无效时回退到 400 DIP，超范围值夹取到有效范围。
3. 按当前 DPI 将逻辑高度转换为屏幕尺寸，并根据主窗口所在屏幕工作区限制实际窗口高度和位置，避免超出可用区域。`window_position` 继续单独保存主窗口位置。
4. 列表使用主窗口剩余客户区并自然滚动；所有配置抽屉始终保留，不设置可视行数，不隐藏、删除或重排抽屉。

**验收：** 调整高度后主窗口即时预览，保存并重启后保持；取消或点击外部关闭设置时还原原高度；所有抽屉仍可通过滚动访问；不同 DPI 和较小工作区下窗口均保持在可用屏幕范围；主题及其他设置不受影响。

### 建议实施顺序与回归

建议先完成 **5.1 响应式加载**，再完成 **5.2 标题栏与底栏**；随后先实现抽屉配置仓储和稳定的目标项更新，再实现 **5.3 列表拖动排序与右键设置**，最后完成 **5.4 主窗口高度设置**。改动前重新检查工作区及相关窗体、Designer、配置仓储的现有差异；不覆盖用户已有修改。

回归至少覆盖：目录内容很多及大量图片时打开/刷新/关闭、损坏或不可访问的图片、窗口边缘缩放、路径入口 Shell 打开失败、拖动排序保存与重启恢复、抽屉路径变更和删除、旧 TOML 缺少新增字段、颜色空值和透明度，以及窗口高度的上下限、DPI 换算和屏幕工作区适配。保持单个 WinForms 项目，不引入新的 UI 框架或 UI 自动化测试框架。
