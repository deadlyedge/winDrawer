# winDrawer 后续开发计划：首次运行默认值与界面收尾

> 状态：需求整理，尚未实施。
>
> 本计划承接 [`DEVELOPMENT_PLAN.md`](DEVELOPMENT_PLAN.md) 已完成的抽屉管理、主题和窗口体验工作，将 [`TODOs.md`](TODOs.md) 中的待办收敛为可实施、可验收的阶段。实施时以用户最新明确要求为准；若与现有开发约定冲突，先记录并更新相应文档。

## 1. 目标

1. 首次创建用户设置时，以仓库根目录的 `Drawer-settings.toml` 作为默认配置来源；不得覆盖用户已经存在的设置文件。
2. 删除已不再需要的旧配置格式兼容读取代码，保留对当前格式的校验和可恢复错误处理。
3. 让抽屉专属颜色也可通过 H/S/L 控件选择，并复用现有颜色转换逻辑。
4. 整理主设置窗口分区，并统一抽屉设置窗口的应用字体。
5. 改善抽屉内容窗口上边框和底部图标按钮的视觉效果。
6. 运行期间不在 Windows 任务栏显示应用按钮；系统托盘仍是应用的常驻入口。

## 2. 已核实的现状与关键决策

- 项目使用 `net10.0-windows`、WinForms、SunnyUI 和 Tomlyn，继续保持单项目结构，不引入新的 UI 框架。
- 根目录实际配置名为 `Drawer-settings.toml`（大小写以仓库文件为准）。它目前已有跟踪且包含工作区改动，实施前必须重新检查并保留这些改动；不要把真实用户路径或个人设置复制进公开模板。
- 当前活动用户设置位于 `%USERPROFILE%\.config\winDrawer\Drawer-settings.toml`。首次创建逻辑在 `SettingsRepository.LoadOrCreateTable`，现阶段不存在时会调用内置的 `CreateDefaultTable`。
- 根目录配置应被当作**新用户的初始化模板**，而不是每次启动时覆盖用户设置的来源。若活动设置已经存在，保持其内容、注释、抽屉顺序和用户数据不变。
- 单文件发布/从快捷方式启动时，不能假定当前工作目录是仓库根目录。模板必须由项目显式随应用部署（或作为嵌入资源读取）；不得依赖 `Environment.CurrentDirectory` 恰好指向仓库。
- 当前主题颜色转换入口为 `ThemePalette.FromHsla`；抽屉蒙版当前以 `overlay_color = "#RRGGBB"` 持久化，并由 `ThemePalette.BlendOverlayColor` 固定按 70% 混合。建议把 H/S/L 作为抽屉设置的**交互方式**，继续保存规范化 RGB 字段，暂不另造一套 TOML 颜色格式；抽屉蒙版强度仍固定为 70%，不增加 Alpha 控件。
- `SettingsForm` 已按 Behavior、Visual、General 分区。整理分区时先盘点现有控件和行为，目标是更清楚的分组和对齐，不删除或悄然改变功能。
- `DrawerSettingsDialog` 已加载品牌字体文件，但各类控件的字体使用不完全一致。统一字体时必须保留无字体文件/字体加载失败时的系统字体回退，并明确 `Font`、`PrivateFontCollection` 的所有权和释放时机。
- `DrawerWindow` 通过移除 `WS_CAPTION` 隐藏标题栏，Designer 仍设置 `FormBorderStyle.Sizable`；底部刷新/关闭按钮使用 Segoe MDL2 Assets 字形，当前主题应用代码也会给按钮设置主题颜色。边框和图标颜色问题应在实际窗口截图/运行效果下定位，不能只凭静态属性假定已解决。
- 抽屉窗口及抽屉设置对话框已经设置 `ShowInTaskbar = false`；主窗口当前未显式设置该属性。目标是任务栏没有应用按钮，同时仍保留主窗口与托盘菜单现有的显示/隐藏、设置和退出入口。除非另有确认，不把本需求解释成“应用启动后必须隐藏主窗口”。

## 3. 产品行为与数据安全约定

### 3.1 首次启动配置

- 仅当 `%USERPROFILE%\.config\winDrawer\Drawer-settings.toml` 尚不存在时，使用随应用部署的根目录 `Drawer-settings.toml` 初始化它。
- 若活动配置已经存在，无论模板内容如何变化，均不得覆盖、合并或重置活动配置。
- 将模板作为应用内容或嵌入资源明确纳入 Debug、Release 和单文件发布；定位方式不得依赖当前工作目录。
- 初始化前验证模板可解析且符合当前 schema。若模板缺失或无效，记录可诊断日志并采用明确的安全恢复行为；不得创建半截文件、静默覆盖现有文件或让应用异常退出。是否采用内置默认值作为恢复后备，应在实现时与现有错误处理保持一致并增加测试。
- 活动设置文件应使用安全写入方式创建；若首次写入失败，向用户报告可理解的错误，不得假报初始化成功。
- 根目录 TOML 是可随版本维护的默认模板，不是发布后更新用户偏好的机制。模板示例应避免包含开发机私有路径和个人数据。

### 3.2 移除旧格式兼容

- 实施前先列出当前代码和配置文档中的旧格式兼容分支，至少核查 TOML 类型兼容、旧数组/表表示、旧颜色表示和字段别名；依据当前正式 schema 确认哪些确为旧格式。
- 删除已明确废弃格式的读取/转换分支，统一只接受 `docs/CONFIGURATION_FORMAT.md` 定义的当前格式。
- 不把“移除兼容”扩大为移除当前格式的类型校验、范围夹取、缺字段默认值、非法条目隔离、未知字段策略或错误报告。这些是可靠性/数据保护行为，不应仅因名称上像兼容逻辑而删除。
- 不自动迁移、搜索、复制或删除其他目录中的旧配置，也不因格式不支持就覆盖原活动设置。遇到 TOML 语法错误或不受支持的格式时，应保留原文件并给出可恢复提示。
- 同步更新配置格式文档和测试清单，明确当前支持的格式及不再支持的旧格式；升级说明应提示受影响用户如何手动备份或整理数据。

### 3.3 抽屉颜色的 H/S/L 调色

- 在抽屉设置中提供 H/S/L 调节和颜色预览，交互风格尽量复用主题设置现有的 H/S/L 控件及颜色转换代码。
- 抽屉颜色不使用主题窗口的 Alpha/透明度值；显示效果继续固定为 70% 蒙版。
- 建议沿用现有 `overlay_color = "#RRGGBB"` 存储格式：从 H/S/L 转换为 RGB 后保存，以避免无必要的配置 schema 改动。若实现发现必须改存 HSL，先单独评估迁移与文档方案，不得静默改变字段语义。
- “不叠加”仍是有效状态；取消/关闭设置窗口不应写入颜色，保存只修改目标抽屉。
- 复用颜色转换逻辑，不复制一份 HSL 算法。只有当控件创建逻辑能实际复用且不会引入不必要抽象时，才抽取小型共享控件/辅助方法。

## 4. 分阶段实施与验收

### 阶段 6.1：首次启动模板与兼容清理

1. 重新检查工作树、根目录 `Drawer-settings.toml` 的当前内容及设置仓储的 diff；不覆盖用户已有改动。
2. 将根目录模板明确纳入构建和发布输出；验证以不同工作目录启动、Debug/Release、框架依赖的 win-x64 单文件发布均可定位模板。
3. 调整首次创建流程：活动用户配置不存在时，以当前模板内容生成；活动配置存在时原样读取且不受模板更新影响。
4. 清点并删除确认废弃的旧 schema 解析分支，保留当前格式所需校验及安全错误处理。
5. 更新 `CONFIGURATION_FORMAT.md`，说明默认模板、首次初始化条件、活动设置位置、不支持的旧格式及手动处理方式。
6. 为纯配置逻辑补充有针对性的测试，不新增 UI 自动化框架。

**验收：** 新用户首次运行得到的有效配置值与模板一致；再次启动或更新模板都不会覆盖既有用户设置；从非项目目录和发布目录运行时模板仍可找到；模板损坏/缺失、活动配置损坏和写入失败均不会破坏现有用户文件；旧格式明确拒绝或按已记录规则处理，当前格式继续正常工作。

### 阶段 6.2：抽屉 H/S/L 颜色设置

1. 将当前抽屉颜色对话框交互替换/扩展为 H/S/L 控件和实时预览，保留清除蒙版入口。
2. 复用主题颜色转换函数；抽屉色保存为 `#RRGGBB`，应用时仍按 70% 混合，不读取主题 Alpha。
3. 验证主窗口抽屉项、抽屉内容窗体、实时主题预览及颜色更新后的一致性。
4. 为 H/S/L 边界、RGB 输出和 70% 混色逻辑补充纯逻辑测试。

**验收：** H/S/L 边界值生成稳定 RGB；调整时预览即时更新；保存/取消/清除行为正确；重启后颜色保持；透明度仍固定 70%；更改一个抽屉不会影响其他抽屉、主题 HSLA 或用户文件。

### 阶段 6.3：主设置窗口分区与抽屉设置字体

1. 先盘点 `SettingsForm` 当前所有控件、事件、持久化字段及 Behavior、Visual、General 分区；列出每个设置项归属后再调整布局。
2. 保留所有现有设置和实时预览/取消/保存行为，只改善分区标题、顺序、留白、对齐及不同 DPI 下的可读性。
3. 明确主窗口与抽屉设置对话框的品牌字体/系统字体层级，对标签、输入框、按钮、说明文字统一应用；不要求图标字体与普通文本字体相同。
4. 字体文件不可用或加载失败时使用清晰一致的系统字体；保证字体集合、派生字体和控件释放顺序正确。

**验收：** 原设置项及保存结果未丢失；分区标题与控件语义匹配；保存、取消、实时预览保持原行为；抽屉设置控件字体层级统一，缺失字体时仍可正常操作；高 DPI 下无裁切或重叠，字体资源无泄漏。

### 阶段 6.4：抽屉窗口边框与主题按钮

1. 在目标 Windows 环境记录当前抽屉窗口上边框表现，并检查非客户区样式、缩放边框、DPI 和主题背景，确认粗边缘的来源。
2. 最小化调整无标题栏窗口样式，去除多余的顶部框/留白；除非明确取消，不破坏现有窗口边缘缩放、最小尺寸、底部关闭按钮及抽屉尺寸保存行为。
3. 按当前主题背景为刷新和关闭图标设置适当前景色/状态色；检查普通、悬停、按下、禁用状态，并保证深浅背景下图标对比度足够。
4. 继续使用可访问名称和提示；不为简单图标按钮引入新的图标包或自绘整套控件。

**验收：** 标题栏仍隐藏且上边缘不再有明显多余厚边；可调整窗口大小的边缘和最小尺寸仍有效；刷新/关闭按钮在浅色、深色及专属抽屉蒙版下清晰可辨，交互状态与主题一致；不改变抽屉内容、路径入口和关闭行为。

### 阶段 6.5：托盘优先且不显示任务栏按钮

1. 明确主窗体不创建任务栏按钮，并核实 WinForms 窗口样式、激活、置顶/切换及 Alt+Tab 行为，不意外隐藏或损坏主界面。
2. 启动时继续按现有产品行为显示主界面，除非另行确认需要改成默认隐藏；系统托盘图标始终可用并能显示/隐藏主窗口、打开设置和退出。
3. 检查主窗体、抽屉窗体、设置窗体的任务栏归属，避免任何辅助窗口创建重复任务栏入口。
4. 验证托盘图标创建失败、应用退出和窗体显示/隐藏切换时资源正确释放、状态一致。

**验收：** 应用运行时任务栏没有 winDrawer 按钮，托盘只有预期的应用图标；主窗口仍可从托盘正常显示、激活、隐藏；设置、抽屉操作和退出均可用；重复显示/隐藏不产生额外任务栏按钮或孤立窗口。

### 阶段 6.6：文档与回归

1. 更新 `README.md`、`CONFIGURATION_FORMAT.md` 和必要的设置/使用说明，使首次运行模板、H/S/L 抽屉颜色、窗口外观与托盘行为与实际一致。
2. 审阅旧格式兼容相关代码、注释和文档，确保不再承诺已删除的读取行为。
3. 执行 Windows Release 构建、针对性自动化测试和单文件发布验证；不清理用户的 `bin/`、`obj/`、发布目录、日志或 `.vs/` 文件。
4. 手动回归首次运行、已有用户配置、主题和抽屉颜色、不同 DPI、抽屉缩放、托盘显示/隐藏、退出及任务栏行为。

**验收：** 构建与针对性测试通过；单文件产物包含所需模板资源；配置文档与实际 schema 一致；窗口及托盘行为满足本计划；未覆盖用户配置、工作区改动或用户数据。

## 5. 建议实施顺序

先完成 **6.1 配置模板与 schema 清理**，以确定抽屉颜色的持久化契约；再完成 **6.2 抽屉 H/S/L 设置**。随后并行度较低地依次完成 **6.3 设置页与字体**、**6.4 抽屉窗口外观**、**6.5 托盘/任务栏行为**，最后完成 **6.6 文档与回归**。每阶段先检查 `git status --short`、目标文件现有内容和 diff；存在冲突时保留用户改动并缩小补丁。

## 6. 本阶段不做

- 不覆盖、自动合并或迁移已存在的用户配置，不删除旧配置文件或用户数据。
- 不仅为抽屉 H/S/L 调色而修改主题页现有 HSLA 交互，或将抽屉蒙版 70% 改成可调透明度。
- 不因“清除旧兼容”而移除当前 schema 的健壮校验、错误提示和未知字段保护。
- 不把无任务栏按钮擅自扩大成启动后强制隐藏主窗口。
- 不重写整个窗口框架、不引入大型颜色选择器/图标库/UI 自动化框架，也不修改与本计划无关的文件列表和 Shell 行为。
