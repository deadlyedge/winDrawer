# winDrawer 后续开发计划：首次运行默认值与界面收尾

> 状态：阶段 6.1–6.6 已实施；阶段 6.7 的文档更新、配置 smoke checks、Release 构建和单文件发布验证已完成。阶段 6.4–6.6 用户反馈基本正常，长期使用回归继续进行。
>
> **后续 UI 状态：** SunnyUI 已在后续迁移中完全移除。阶段 6 描述的 Lobster 按钮、圆角/状态色和设置页控件为当时实现；当前按钮为原生扁平 `Button`（主操作 10F、其他 9.5F），设置页使用原生 GroupBox/TrackBar/CheckBox，抽屉滚动条为 `ThemedScrollBar`。具体见 [`WHITEPAPER.md`](../WHITEPAPER.md)。
>
> 本计划承接 [`DEVELOPMENT_PLAN.md`](DEVELOPMENT_PLAN.md) 已完成的抽屉管理、主题和窗口体验工作，将 [`TODOs.md`](../TODOs.md) 中的待办收敛为可实施、可验收的阶段。实施时以用户最新明确要求为准；若与现有开发约定冲突，先记录并更新相应文档。

## 1. 目标

1. 首次创建用户设置时，以仓库根目录的 `Drawer-settings.toml` 作为默认配置来源；不得覆盖用户已经存在的设置文件。
2. 删除已不再需要的旧配置格式兼容读取代码，保留对当前格式的校验和可恢复错误处理。
3. 精简颜色设置界面，移除 H/S/L 滑块，使用 Windows 系统颜色控件选择主主题色和抽屉专属色，并评估系统控件可定制范围。
4. 整理主设置窗口分区，并统一抽屉设置窗口的应用字体。
5. 窗口锁定时不显示移动/拖动提示；改善抽屉内容窗口上边框和底部图标按钮的视觉效果。
6. 运行期间不在 Windows 任务栏显示应用按钮；系统托盘仍是应用的常驻入口。

## 2. 已核实的现状与关键决策

- 项目使用 `net10.0-windows`、WinForms 和 Tomlyn，继续保持单项目结构，不引入新的 UI 框架；SunnyUI 已在后续迁移中移除。
- 根目录实际配置名为 `Drawer-settings.toml`（大小写以仓库文件为准），作为新用户首次运行模板；模板不得包含真实用户路径或个人抽屉配置。
- 当前活动用户设置位于 `%USERPROFILE%\.config\winDrawer\Drawer-settings.toml`。首次创建逻辑在 `SettingsRepository.LoadOrCreateTable`；用户配置不存在时从程序集内嵌的根目录模板初始化。
- 根目录配置应被当作**新用户的初始化模板**，而不是每次启动时覆盖用户设置的来源。若活动设置已经存在，保持其内容、注释、抽屉顺序和用户数据不变。
- 单文件发布/从快捷方式启动时，不能假定当前工作目录是仓库根目录。模板必须由项目显式随应用部署（或作为嵌入资源读取）；不得依赖 `Environment.CurrentDirectory` 恰好指向仓库。
- 阶段 6.2 前主主题区曾使用 H/S/L 滑块。现已改为可点击的 RGB 颜色预览和独立透明度滑块；抽屉颜色继续通过 WinForms `ColorDialog` 选择，并以 `overlay_color = "#RRGGBB"` 持久化，固定按 70% 混合。主题颜色统一以 `#RRGGBB` 表示，透明度独立保存，不使用 HSLA 设置字段。
- 新 UI 与配置要求优先于旧计划和 `AGENTS.md` 中保留 H/S/L/HSLA 控件的旧约定；已同步更新 `AGENTS.md`。程序尚未发布，不实现 HSLA 运行时迁移；开发用用户目录配置直接按新格式修改，保留颜色/透明度数值及其余设置。
- 目标 TOML 字段为 `startup.window_color = "#RRGGBB"` 与 `startup.window_opacity`（整数百分比，与透明度滑块的 0–100 范围一致）；抽屉继续使用 `drawers[].overlay_color = "#RRGGBB"` 并固定 70% 混合。主题内部可按需要推导派生颜色，但不得把 HSLA 作为设置 UI 或持久化字段。
- 系统颜色控件的可定制范围应先通过 WinForms/Windows 实际能力评估，例如初始颜色、完整颜色选择模式、预设颜色和自定义颜色列表；采用系统控件本身支持且可验证的选项，不以自绘控件复刻 H/S/L 面板。
- `ColorDialog` 评估结果：`Color` 设置打开时的当前颜色；`AllowFullOpen = true` 允许进入自定义颜色面板，`FullOpen = true` 初始展开该面板；`AnyColor = true` 显示完整基本颜色集；`CustomColors` 使用整数 BGR/`COLORREF` 色值数组。Windows 公共对话框有 16 个自定义颜色槽，应用传入 16 个值并将当前颜色/应用预设色放入其中。`SolidColorOnly` 用于限制为纯色选择，主要影响 256 色及以下系统中的组合色显示。WinForms 未提供修改原生对话框字体、布局、控件位置或主题的属性；这些外观保持 Windows 公共对话框默认行为。模态原生对话框没有选择变化事件，应用在用户确认后立即更新主题预览，取消选择则保持现值。
- `SettingsForm` 已按 Behavior、Visual、General 分区。整理分区时先盘点现有控件和行为，目标是更清楚的分组和对齐，不删除或悄然改变功能。
- 阶段 6.3 已按用户确认实现：Default 从嵌入模板立即重置受支持的 startup 选项，需用户确认并同步 Windows 登录启动注册；Save/Cancel 管理后续草稿，Cancel 不撤销已确认的 Default。所有写盘都会删除废弃的 `icon_size`，其它未知 startup 键仍予保留。主设置窗体点外不关闭；按钮使用 Lobster，其他文本使用系统字体；按钮语义色统一为保存绿、取消/退出红、其他蓝。
- 抽屉设置标题使用英文 `Drawer settings: {drawer name}`；独立的 `Overlay color` 区域使用可点击色块，色块内显示英文提示和当前 `#RRGGBB`（未设置时显示 `No overlay`），点击后打开系统颜色对话框；区域内说明蒙版固定以 70% 混合且仅影响当前抽屉。
- `Lobster-Regular.ttf` 作为程序集内嵌资源通过固定资源名加载，并以 `PrivateFontCollection.AddMemoryFont` 在内存中创建字体；主窗口品牌标题/按钮及主设置、抽屉设置的标题和非图标按钮（包括 Save、Cancel、Delete）统一使用该应用内字体。关闭图标使用 Segoe MDL2 Assets；其他标签、输入框和说明文字使用 Segoe UI。字体字节缓冲区和字体集合维持到进程退出，控件使用的派生 Font 在各窗体关闭时释放；资源缺失或加载失败时清晰回退 Segoe UI，不依赖字体是否安装在 Windows。
- `DrawerWindow` 通过移除 `WS_CAPTION` 隐藏标题栏，Designer 仍设置 `FormBorderStyle.Sizable`；底部刷新/关闭按钮使用 Segoe MDL2 Assets 字形。阶段 6 当时为主题代码设置普通、悬停、按下和禁用状态的前景/背景；后续原生按钮迁移后，悬停/按下由 `FlatAppearance` 处理，禁用状态使用 WinForms 原生绘制。收紧外层和底部布局边距不得移除 `WS_THICKFRAME`，实际窗口边框及多 DPI 效果仍须运行时确认。
- 主窗口、抽屉窗口、主设置窗体和抽屉设置对话框正常情况下均显式设置 `ShowInTaskbar = false`；托盘初始化失败时主窗口恢复任务栏按钮，以免失去界面入口。正常情况下仍保留主窗口启动显示及托盘菜单的显示/隐藏、设置和退出入口；不把本需求解释成“应用启动后必须隐藏主窗口”。

## 3. 产品行为与数据安全约定

### 3.1 首次启动配置

- 仅当 `%USERPROFILE%\.config\winDrawer\Drawer-settings.toml` 尚不存在时，使用随应用部署的根目录 `Drawer-settings.toml` 初始化它。
- 若活动配置已经存在，无论模板内容如何变化，均不得覆盖、合并或重置活动配置。
- 将模板作为应用内容或嵌入资源明确纳入 Debug、Release 和单文件发布；定位方式不得依赖当前工作目录。
- 初始化前验证模板可解析且符合当前 schema。若模板缺失或无效，记录可诊断日志并采用明确的安全恢复行为；不得创建半截文件、静默覆盖现有文件或让应用异常退出。是否采用内置默认值作为恢复后备，应在实现时与现有错误处理保持一致并增加测试。
- 活动设置文件应使用安全写入方式创建；若首次写入失败，向用户报告可理解的错误，不得假报初始化成功。
- 根目录 TOML 是可随版本维护的默认模板，不是发布后更新用户偏好的机制。模板示例应避免包含开发机私有路径和个人数据。

### 3.2 移除旧格式兼容

- 实施前先列出当前代码和配置文档中的旧格式兼容分支，至少核查 TOML 类型兼容、旧数组/表表示、旧颜色表示和字段别名；依据当前正式 schema 确认哪些确为旧格式。
- 删除已明确废弃格式的读取/转换分支，统一只接受 `docs/CONFIGURATION_FORMAT.md` 定义的当前格式。
- 不把“移除兼容”扩大为移除当前格式的类型校验、范围夹取、缺字段默认值、非法条目隔离、未知字段策略或错误报告。这些是可靠性/数据保护行为，不应仅因名称上像兼容逻辑而删除。
- 不自动迁移、搜索、复制或删除其他目录中的旧配置，也不因格式不支持就覆盖原活动设置。遇到 TOML 语法错误或不受支持的格式时，应保留原文件并给出可恢复提示。
- 同步更新配置格式文档和测试清单，明确当前支持的格式及不再支持的旧格式；升级说明应提示受影响用户如何手动备份或整理数据。

### 3.3 系统颜色控件与颜色配置

- 主主题定制区域只保留颜色预览和透明度滑块。点击颜色预览打开 Windows/WinForms 系统颜色选择控件；移除 Hue、Saturation、Lightness 滑块、数值标签及独立的颜色选择按钮。
- 抽屉专属色也通过系统颜色控件选择；可以保留抽屉设置中的当前颜色预览和“不叠加”入口。
- 评估 `ColorDialog` 等系统控件可配置的初始颜色、完整/标准选择模式、预设颜色及自定义颜色列表。以 Windows 原生对话框的真实能力为边界；系统不支持的外观定制不通过自绘颜色选择器补做。
- 主主题颜色统一保存为 `startup.window_color = "#RRGGBB"`；透明度独立保存为 `startup.window_opacity` 整数百分比（0–100）。不再保留或写入 `window_color_hsla`。
- `drawers[].overlay_color` 继续使用相同的 `#RRGGBB` 形式；不设置时表示无专属蒙版，设置后仍固定以 70% 混合，不增加抽屉透明度字段。
- 应用不包含旧 HSLA 配置的运行时迁移或兼容读取；本次开发阶段直接手动将开发者用户目录配置改为新 schema。未来若考虑正式发布，迁移策略另行讨论，不属于本阶段。
- 抽屉专属颜色不使用主主题 Alpha；显示效果继续固定为 70% 蒙版。“不叠加”仍有效；取消对话框不得写入颜色，保存只修改目标抽屉。
- 复用现有 WinForms `ColorDialog` 和 `ThemePalette` 的主题派生/对比度逻辑；删除持久化 HSLA 所需的设置控件与模型耦合。若主题派生内部继续使用颜色空间转换，应作为实现细节，不形成 UI 或配置契约。

## 4. 分阶段实施与验收

### 阶段 6.1：首次启动模板、颜色 schema 与兼容清理

1. 重新检查工作树、根目录 `Drawer-settings.toml` 的模板内容及设置仓储的 diff；不覆盖用户已有改动。
2. 将根目录模板明确纳入构建和发布输出；模板使用 `startup.window_color = "#RRGGBB"`、`startup.window_opacity`，抽屉颜色继续使用 `drawers[].overlay_color = "#RRGGBB"`；验证不同工作目录、Debug/Release 和框架依赖单文件发布均可定位模板。
3. 调整首次创建流程：活动用户配置不存在时，以当前模板内容生成；活动配置存在时不受模板更新影响。
4. 不实现 `window_color_hsla` 自动迁移/兼容代码；直接手动修改开发者用户目录配置为新字段，逐项保留现有颜色、透明度、位置、窗口尺寸和其它有效配置。
5. 清点并删除确认废弃的旧 schema 解析分支，包括 HSLA 设置字段、旧数组/表形式、字符串标量兼容和 8 位抽屉颜色；保留当前格式校验及安全错误处理。
6. 更新 `CONFIGURATION_FORMAT.md`，说明新字段、模板初始化和不再支持的旧字段/格式。
7. 为模板初始化、RGB 十六进制格式校验和失败恢复做纯逻辑 smoke checks，不新增 UI 自动化框架或测试项目。

**验收：** 新用户首次运行的值与模板一致；更新模板不会覆盖既有用户设置；当前开发用用户目录配置使用新颜色/透明度字段并保留其它设置；程序不读取或迁移 HSLA；从非项目目录和发布目录运行仍可找到模板；当前格式及错误处理正常。

### 阶段 6.2：系统颜色选择与主题面板精简

1. 评估 Windows/WinForms 系统颜色对话框可定制项，并记录可用选项和系统限制；确定颜色预览作为打开颜色对话框的唯一入口。
2. 主主题区域仅保留可点击颜色预览和透明度滑块；颜色选择实时更新预览，透明度独立更新主题预览，取消整页设置时还原两者，保存时分别写入 `window_color` 和 `window_opacity`。
3. 抽屉设置沿用系统颜色对话框并以当前颜色初始化，保留预览和清除蒙版入口。
4. 所有主题颜色保存为规范 `#RRGGBB`；不再通过 UI 或 TOML 保存 HSLA。内部派生色和前景对比度按 RGB 颜色工作，保留现有主题效果意图。
5. 验证主窗口、抽屉项、抽屉内容窗体、主题实时预览及颜色/透明度保存与取消一致；为 RGB 十六进制解析、透明度范围和 70% 混色补充纯逻辑测试。

**验收：** 主主题设置区只有颜色预览和透明度滑块；点击预览打开系统颜色控件；保存的数据只有 `#RRGGBB` 主题色字段和独立透明度字段，不再写入 HSLA；取消恢复原值，重启后值保持；抽屉颜色格式一致且蒙版仍固定 70%；更改主题或某个抽屉不影响其它配置。

### 阶段 6.3：主设置窗口分区与抽屉设置字体

1. 先盘点 `SettingsForm` 当前所有控件、事件、持久化字段及 Behavior、Visual、General 分区；列出每个设置项归属后再调整布局。
2. 保留所有现有设置和实时预览/取消/保存行为，只改善分区标题、顺序、留白、对齐及不同 DPI 下的可读性。
3. 明确主窗口与抽屉设置对话框的品牌字体/系统字体层级，对标签、输入框、按钮、说明文字统一应用；不要求图标字体与普通文本字体相同。
4. 字体文件不可用或加载失败时使用清晰一致的系统字体；保证字体集合、派生字体和控件释放顺序正确。

**验收：** 原设置项及保存结果未丢失；分区标题与控件语义匹配；保存、取消、实时预览保持原行为；抽屉设置控件字体层级统一，缺失字体时仍可正常操作；高 DPI 下无裁切或重叠，字体资源无泄漏。

**状态：已实施。** Default 确认后立即应用嵌入模板中的支持字段并保存，后续编辑可由 Cancel 撤销至 Default 后基线；主设置窗口只通过 Save、Cancel 或关闭 App 关闭，不因点外而退出；设置标题和 Save/Cancel/Delete 使用 Lobster，其余文本为英文系统字体，按钮颜色语义统一；窗口高度滑块与透明度滑块使用同款控件样式。抽屉设置中的 Overlay color 色块和 70% 混合说明位于独立且加大的区域，色块沿用主设置的点击选择设计；阶段 10 已修复颜色区溢出，并使用阻尼 DPI 缩放（200% 下窗口约 930×775），96/192 DPI 离屏探针验证边界，100%/150% 与真实交互仍需人工回归。

### 阶段 6.4：锁定状态与移动提示

1. 检查主窗口的拖动处理、标题区域鼠标样式/图标及锁定设置的应用时机，确认用户所说的“移动图标”具体对应的视觉提示。
2. 当 `window_locked = true` 时，不显示移动图标/拖动光标等暗示窗口可移动的提示；主窗口拖动操作继续无效。
3. 解锁后恢复现有可移动行为及相应提示；锁定状态变化后应立即同步 UI，不必重启应用。
4. 保留设置窗体自身必要的交互，不要把主窗口锁定设置误用于设置对话框或抽屉内容窗口。

**验收：** 锁定时主窗口不可拖动且无移动提示；解锁后移动功能与提示恢复；切换锁定状态即时生效；位置持久化、窗口高度和托盘显示/隐藏不受影响。

**状态：已实施。** 锁定设置切换时立即更新主窗口光标并拦截拖动；Cancel 恢复原锁定状态，Save 持久化新值。用户反馈基本正常，长期使用回归继续进行。

### 阶段 6.5：抽屉窗口边框与主题按钮

1. 在目标 Windows 环境记录当前抽屉窗口上边框表现，并检查非客户区样式、缩放边框、DPI 和主题背景，确认粗边缘的来源。
2. 最小化调整无标题栏窗口样式，去除多余的顶部框/留白；除非明确取消，不破坏现有窗口边缘缩放、最小尺寸、底部关闭按钮及抽屉尺寸保存行为。
3. 按当前主题背景为刷新和关闭图标设置适当前景色/状态色；检查普通、悬停、按下、禁用状态，并保证深浅背景下图标对比度足够。
4. 继续使用可访问名称和提示；不为简单图标按钮引入新的图标包或自绘整套控件。

## 6. 本阶段不做

- 不覆盖或自动合并已存在的用户设置，不迁移其它配置文件路径，不删除旧配置文件或用户数据；本阶段仅对开发者当前用户目录的设置文件做经备份的手动颜色字段调整，不实现运行时 HSLA 迁移。
- 不保留主题 H/S/L/HSLA 设置控件或 `window_color_hsla` 持久化字段；主题页只保留颜色预览入口和独立透明度滑块。
- 不将主题透明度合并进颜色字符串；`window_color` 必须是 `#RRGGBB`，透明度必须单独持久化。
- 不为了复刻 H/S/L 滑块而自行绘制系统颜色对话框不支持的 UI；评估结果应说明真实可定制边界。
- 不将抽屉蒙版 70% 改成可调透明度。
- 不因“清除旧兼容”而移除当前 schema 的健壮校验、错误提示和未知字段保护。
- 不把无任务栏按钮擅自扩大成启动后强制隐藏主窗口。
- 不在窗口锁定时保留会暗示可拖动的移动图标或移动光标。
- 不重写整个窗口框架、不引入大型颜色选择器/图标库/UI 自动化框架，也不修改与本计划无关的文件列表和 Shell 行为。


## 7. 阶段 7 收尾记录（承接 [DP_STAGE_7.md](DP_STAGE_7.md)）

阶段 7.1–7.5 已在阶段 6 的成果之上实施完成；本节只记录与阶段 6 决策直接相关的承接结论，详细验收条件见 `DP_STAGE_7.md`。

- **文件列表排序（7.1）**：抽屉直接子项按最后修改时间（`LastWriteTimeUtc`）降序显示，目录与文件混排；时间相同按名称 `OrdinalIgnoreCase` 升序、再按完整路径 `Ordinal` 升序；时间不可读的条目排在最后。**阶段 8.4 更新：** 该顺序是默认值 `drawers[].sort_mode = "newest"`，用户可在抽屉右键菜单切换到 `oldest`/`name` 并持久化；三种模式都保持目录与文件混排。
